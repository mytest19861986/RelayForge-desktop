# RelayForge Studio 4.1.0 — راهنمای فارسی

**نسخه کاندید انتشار (RC):** ارتقای سورس 4.0.0 FULL BUILD R2، نه بازنویسی از صفر. کد و داشبورد واقعی ارائه می‌شوند؛ EXE ویندوز و ارسال واقعی پنج سرویس در محیط حاضر تأیید نشده‌اند.


## راهنمای سریع ۴.۱ — رفع مشکل بله و آرشیو

### حذف مقصدها
از نمای کلی، موتور را متوقف کنید. در «مقصدها و APIها» تیک مقصدهای اضافی را بزنید و «حذف مقصدهای انتخاب‌شده» را انتخاب کنید؛ برای یک مقصد دکمه «حذف مقصد» روی همان کارت است. دو بار تأیید کنید. مقصد از فهرست فعال حذف (بایگانی) و توکن ذخیره‌شده آن خالی می‌شود؛ تاریخچه در گزارش‌ها باقی می‌ماند. صف منتظر ردشده ثبت می‌شود. اگر ارسال نامطمئن یا در جریان وجود دارد ابتدا آن را تعیین تکلیف کنید. حذف گروهی یک تراکنش است. پاک‌کردن صف فقط پیام‌های queued همان مقصد را رد می‌کند. توقف/ادامه مستقل بدون خاموش کردن سایر مقصدها ممکن است؛ ارسال در جریان ممکن است تکمیل شود. تکرار مقصد با همان شناسه متنی در یک سرویس محدود شده و هنگام افزودن backlog، ارسال موفق همان شناسه در همان عملیات دوباره صف نمی‌شود. شناسه‌های معادل با قالب‌های متفاوت و عملیات تازه هنوز خطر تکرار دارند.

### ارسال پست‌های قدیمی تلگرام به بله و دیگر مقصدها
1. موتور را متوقف کنید. در مبدأ، روش **API ID / Hash** را انتخاب کنید. از https://my.telegram.org/apps مشخصات برنامه را دریافت و شماره حساب تلگرام خود را با کد کشور وارد کنید.
2. اگر قبلاً با BotFather در همین عملیات پیام گرفته‌اید، همان شناسه کانال مادر را دقیقاً نگه دارید، گزینه «ارتقای همان کانال به API Hash یا اصلاح اطلاعات ورود حساب» را فعال کنید و ذخیره کنید. در صورت نبود شناسه عددی ذخیره‌شده، برنامه از بات قبلی یک بررسی خواندنی می‌گیرد؛ این بررسی فقط مالکیت/شناسه فعلی را نشان می‌دهد، نه اینکه نام کاربری در گذشته هیچ‌وقت تغییر نکرده باشد. اگر نام کانال تغییر کرده یا از هویت قبلی مطمئن نیستید، به جای این مهاجرت از پروژه جدید استفاده کنید. قبل از خواندن آرشیو، شناسه عددی کانال با شناسه ذخیره‌شده مقایسه می‌شود.
3. درخواست کد و سپس تأیید ورود را انجام دهید؛ اگر رمز دومرحله‌ای دارید همان‌جا وارد کنید. بعد تست مبدأ را بزنید.
4. آرشیو را فعال و بازه مثلاً ۳۰ تا ۲۰۰ را وارد کنید. Realtime اختیاری و مستقل است. برای بازخوانی از شماره شروع، پس از ذخیره «پیمایش مجدد بازه ذخیره‌شده» را بزنید. شناسه‌های قبلاً ثبت‌شده تکرار نمی‌شوند؛ رکوردهای کپی BotFather با محتوای واقعی تکمیل می‌شوند.
5. مقصد بله را فعال کنید، توکن بازوی **بله** (نه BotFather تلگرام) و شناسه کانال بله را وارد کنید. بازو باید در کانال مجوز انتشار داشته باشد. برای پیام‌هایی که قبلاً با محتوای واقعی ثبت شده‌اند، تیک «صف‌کردن پیام‌های قبلی همین عملیات» را هنگام ذخیره بزنید. این گزینه تمام پیام‌های واجد شرایط قبلی همین عملیات را شامل می‌شود، نه فقط بازه تازه؛ اگر نمی‌خواهید چنین شود، پروژه جداگانه بسازید. مقصدهای دیگر نیز مستقل تنظیم می‌شوند.
6. با موتور متوقف، «تست API» و سپس «ارسال پیام آزمایشی» را بزنید؛ دومی یک پیام واقعی منتشر می‌کند. اگر موفق شد، ابتدا بازه کوچک چند پست را امتحان و بعد موتور را شروع کنید.

BotFather به‌تنهایی متن و رسانه آرشیو قدیمی را نمی‌خواند؛ آن روش فقط کپی مستقیم آرشیو به تلگرام یا دریافت پیام‌های جدید را پوشش می‌دهد. هیچ محتوای محافظت‌شده‌ای دور زده نمی‌شود. فرمت‌های خاص، آلبوم کامل، محدودیت اندازه رسانه و قالب متن سرویس مقصد همچنان محدودیت دارند. آرشیو و ارسال واقعی در حساب‌های شما هنوز آزمایش نشده‌اند.

### لاگ و گزارش
روی کارت مقصد، شمارنده‌های صف، موفق، خطا، نامطمئن و ردشده دیده می‌شوند. آخرین خطا و زمان تلاش بعدی نشان داده می‌شود. صفحه «لاگ و وضعیت ارسال» فیلتر مقصد (حتی بایگانی‌شده)، جست‌وجو، صفحه‌بندی ۱۰۰ رکورد و دریافت JSON دارد. برای خروجی پایدار، موتور را متوقف کنید. جست‌وجوی ارسال‌ها شامل وضعیت، شناسه پیام، خطا و نام کانال است. علت رد شدن محتوا، عدم ورود آرشیو BotFather به صف بله، شروع ارسال، خطای API و شناسه پیام مقصد ثبت می‌شود. از این نسخه رویدادهای DB به‌صورت خودکار پس از ۳۰۰۰ رکورد حذف نمی‌شوند؛ حجم دیسک را دوره‌ای بررسی کنید. لاگ فایل `data/logs/relayforge.log` چرخشی است (حدود ۳ مگابایت و ۵ نسخه قبلی)؛ DB منبع اصلی گزارش است. اطلاعات پیش‌تر حذف‌شده بازیابی نمی‌شوند. توکن‌ها و URL خام در شرح خطا ثبت نمی‌شوند. خروجی گزارش ممکن است شناسه کانال‌ها و جزئیات عملیاتی داشته باشد؛ عمومی منتشر نکنید.

## ۱. اجرا

- ویندوز 10/11 و Server 2019 x64 هدف هستند؛ Python 3.12 x64 با Python Launcher نصب باشد. برای اجرای سورس `RUN_FROM_SOURCE_WINDOWS.bat` را اجرا کنید. برای ساخت EXE `BUILD_EXE_WINDOWS.bat` را اجرا کنید. اسکریپت تست‌ها را پاس نکرده به کامپایل نمی‌رود؛ پس از کامپایل نیز خود EXE را با پایگاه داده موقت و HTTP محلی آزمایش می‌کند. هیچ توکن واقعی برای تست لازم نیست.
- بعد از اجرای برنامه، آدرس `http://127.0.0.1:8765` را باز کنید. کلید ورود در `data\dashboard-key.txt` است. این کلید، توکن‌ها و فایل‌های session را به اشتراک نگذارید. موتور در نصب جدید خاموش است. پس از تنظیم مبدأ و مقصدها، دکمه شروع انتشار را بزنید.
- برای ساخت ویندوز، ZIP خروجی `RelayForge_v4.1.0_WINDOWS_EXE.zip` تنها پس از موفقیت تست و کامپایل و smoke test ایجاد می‌شود. سورس Python در ZIP اجرایی نهایی توزیع نمی‌شود؛ کامپایل Nuitka مانع مطلق مهندسی معکوس نیست و HTML/JS قابل مشاهده است.

## ۲. انتخاب روش دریافت

| روش | آرشیو | دریافت زنده | فیلتر محتوا |
|---|---|---|---|
| BotFather | فقط copyMessage به مقصد تلگرام با شناسه شروع و پایان | دریافت channel_post، ارسال به همه مقصدهای فعال | فقط وقتی آرشیو BotFather خاموش است |
| API ID/Hash (Telethon) | خواندن محتوای مجاز و ارسال به همه مقصدها | NewMessage و پیمایش جبرانی پس از اتصال مجدد | متن، کپشن، هشتگ و کلمات |

در حالت BotFather ربات را ادمین مبدأ کنید. برای کپی مستقیم آرشیو، بات مقصد نیز باید به مبدأ و مقصد دسترسی داشته باشد. شماره‌ها Message ID واقعی هستند، نه ترتیب پست. هر پست آرشیو با شناسه ثبت می‌شود؛ وجود همه پست‌ها یا موفقیت کپی تضمین نمی‌شود. خطاهای ارسال در صف همان مقصد قابل تعیین تکلیف‌اند. برای انتشار آرشیو ایتا، بله، روبیکا و سروش، API ID/Hash لازم است. Bot API به متن تاریخچه دلخواه دسترسی نمی‌دهد و آپدیت‌ها پس از حداکثر ۲۴ ساعت ممکن است از دست بروند. حفاظت محتوا دور زده نمی‌شود.

در حالت API Hash، از my.telegram.org کلیدهای برنامه را بگیرید، شماره حساب خود را وارد کنید، ذخیره کنید، درخواست کد و سپس تأیید ورود را انجام دهید. برنامه فقط برای حساب و محتوا با مجوز استفاده شود. نشست‌های نسخه ۴ با نام وابسته به مشخصات حساب ذخیره می‌شوند؛ پس از مهاجرت از ۳ ممکن است ورود مجدد نیاز باشد. نشست قبلی حذف نمی‌شود. کد ورود را به فرد دیگری ندهید.

آرشیو و Realtime مستقل هستند: بازه ۳۰ تا ۲۰۰ فقط آرشیو را محدود می‌کند؛ پست جدید ۲۰۱ نیز در صورت فعال بودن Realtime به صف می‌رود. حالت ارسال فوری هر مقصد فاصله صفر دارد؛ فاصله ۱۰۸۰۰ ثانیه برابر سه ساعت است. اولویت پیام‌های زنده برای مقصد فوری است. برای جلوگیری از رفتار ناخواسته، تغییر تنظیمات اصلی هنگام اجرای موتور مسدود است؛ ابتدا توقف امن بزنید.

## ۳. مقصدها و فیلتر

پنج نوع پیام‌رسان پیش‌فرض و حداکثر ۵۰ مسیر مقصد مستقل. با «افزودن مقصد» می‌توانید چند کانال تلگرام یا چند کانال از یک سرویس تعریف کنید. هر مسیر توکن، شناسه کانال و زمان‌بندی جدا دارد. فقط مقصدهای فعال صف جدید دریافت می‌کنند. گزینه «صف‌کردن پیام‌های قبلی همین عملیات» پیش‌فرض خاموش است. برای ارسال آرشیو ذخیره‌شده به مقصد جدید آن را صریحاً انتخاب کنید. برای تغییر توکن همان مقصد، ابتدا موتور را متوقف کنید و توکن را ذخیره کنید؛ سابقه حذف نمی‌شود. تغییر شناسه مقصد دارای سابقه در عملیات فعال مسدود است؛ مقصد جدید بسازید یا عملیات را بازنشانی کنید.

در صفحه مبدأ، فیلتر را روشن کنید و عبارت‌ها را با ویرگول فارسی یا انگلیسی جدا کنید. نوع تطبیق حداقل یکی یا همه؛ کلمات ممنوع همیشه پیام را رد می‌کنند. هشتگ دقیق بررسی می‌شود، کلمه کلیدی جستجوی زیررشته‌ای است. متن قبل/بعد اختیاری است. فیلتر فقط پیام‌هایی را که پس از تنظیم وارد می‌شوند بررسی می‌کند؛ صف قبلی بازنویسی نمی‌شود. آرشیو BotFather با فیلتر یا افزودن متن مجاز نیست.

## ۴. خطا و بازیابی

- قطعی پیش از ارسال و HTTP 429: تلاش مجدد امن بعد از حداقل ۳۰ ثانیه و رعایت Retry-After. در قطع پاسخ بعد از POST یا پاسخ نامعتبر، وضعیت uncertain ذخیره و فقط همان مسیر متوقف می‌شود؛ دستی مقصد را بررسی کنید. پاسخ HTTP 5xx نیز نامطمئن است. هیچ تضمین exactly-once بدون پشتیبانی مقصد وجود ندارد.
- سه خطای قطعی متوالی، همان مقصد را غیرفعال می‌کند. با اصلاح و فعال‌سازی دوباره مسیر ادامه دهید. خطاهای رسانه قبل از ارسال به تعویق می‌افتند. برنامه وب در قطعی اینترنت بسته نمی‌شود.
- توقف موتور، ارسال در جریان را محافظه‌کارانه نامطمئن علامت می‌زند. بعد از ری‌استارت، موتور فقط اگر قبلاً از پنل روشن بوده دوباره روشن می‌شود. تاریخچه و صف ذخیره می‌شوند.
- صفحه لاگ و وضعیت ارسال: تعیین تکلیف دستی failed/uncertain با retry، mark sent یا skip. قبل از retry وضعیت واقعی کانال را بررسی کنید.
- کش رسانه سقف عملیاتی اولیه ۱ گیگابایت و حداقل فضای آزاد دارد؛ دانلود Bot API ابری تا ۲۰ MB (محدودیت تلگرام). سقف فایل تنظیم‌شده نیز رعایت می‌شود. فایل‌های قدیمی خودکار حذف نمی‌شوند تا ارسال‌های معوق آسیب نبینند؛ پاک‌سازی خودکار کامل و حفظ آلبوم یکجا هنوز توسعه نیاز دارند.

## ۵. بازنشانی عملیات و مهاجرت از نسخه ۳

ابتدا نسخه ۳ را کاملاً متوقف کنید. از کل پوشه `data` (DB، secrets.key، session، media، logs و dashboard-key) پشتیبان رمزگذاری‌شده بگیرید. **هیچ فایل واقعی شما در بسته وجود ندارد.** نسخه ۴ را در پوشه تازه استخراج کنید و فقط کپی پوشه data را در کنار EXE یا main.py قرار دهید. مهاجرت DB افزودنی است و تاریخچه حفظ می‌شود. قبل از کپی داده حتماً از داشبورد نسخه قبلی دکمه توقف موتور را بزنید تا run_enabled=false ذخیره شود؛ اگر وضعیت روشن قبلی باقی مانده باشد، نسخه جدید هنگام اجرا موتور را آغاز می‌کند. پوشه قبلی را تا آزمون واقعی نگه دارید.

در تب عملیات، Backup یک نسخه سازگار SQLite و کلید رمزنگاری می‌سازد؛ رسانه و session در این Backup خودکار نیستند. برای پشتیبان کامل، در حالت توقف تمام پوشه data را کپی کنید. از فایل‌های کلید و پشتیبان محافظت کنید.

«بازنشانی با دو تأیید»: عملیات فعلی بایگانی، صف‌های در انتظار رد و مقصدها غیرفعال می‌شوند. تاریخچه موفق قبلی حفظ می‌شود و مبدأ و مقصد برای عملیات تازه قابل تنظیم هستند. ارسال‌های نامطمئن باید ابتدا تعیین تکلیف شوند. این کار پست‌های منتشرشده را حذف نمی‌کند و ارسال مجدد ممکن است تکراری باشد.

## ۶. چند پروژه، اجرای دائمی Windows

`START_PROJECT.bat` در بسته اجرایی، نام پروژه و پورت محلی منحصربه‌فرد می‌گیرد. هر پروژه دیتابیس و کلید جدا دارد. در سورس:

```
py -3.12 main.py --data-dir projects\news --port 8766
py -3.12 main.py --data-dir projects\education --port 8767
```

هر نمونه فقط یک کانال مادر دارد؛ چند پروژه را جداگانه اجرا کنید. از یک BotFather token برای getUpdates همزمان در چند پروژه استفاده نکنید. پنل مرکزی سوییچ پروژه‌ها هنوز پیاده نشده است.

برای VPS، Task Scheduler پیشنهاد می‌شود: `INSTALL_AUTO_START.ps1` را در PowerShell با دسترسی مدیر و حساب اختصاصی کم‌اختیار اجرا کنید. تسک At startup ثبت می‌شود؛ پس از تست، Disconnect RDP مشکلی ندارد. برنامه را از مسیر ثابت و با ACL محدود اجرا کنید. از حساب عادی سرویس استفاده کنید، نه Administrator. برای نصب اختیاری Windows Service، اسکریپت `INSTALL_SERVICE_WINDOWS.ps1` در Program Files محافظت‌شده و data در ProgramData با ACL محدود؛ حساب اختصاصی غیرادمین دارای Log on as a service لازم است. این مسیر هنوز روی ویندوز آزمایش نشده است. هر دو روش را همزمان نصب نکنید. نصب/حذف Task و Service از داخل داشبورد فعلاً انجام نمی‌شود. برای توقف/حذف از ابزار رسمی Windows استفاده کنید. تنظیمات موتور در DB باقی می‌ماند.

## ۷. امنیت و حدود تأیید

- localhost فقط؛ پورت را روی اینترنت عمومی باز نکنید. از Remote Desktop یا تونل امن استفاده کنید.
- توکن‌ها در SQLite با Fernet رمزگذاری می‌شوند، ولی کلید روی همان دیسک است. ACL و امنیت حساب سیستم ضروری است. توکن‌ها و OTP به صورت عمومی نمایش داده نمی‌شوند.
- تست Telegram و Bale تلاش می‌کند getMe/getChat/getChatMember را بدون ارسال بررسی کند. ایتا، روبیکا و سروش فعلاً تست اعتبار API دارند؛ مجوز واقعی انتشار باید با کانال آزمایشی تأیید شود. خطای 404 ممکن است مسیر API/توکن نامعتبر باشد؛ ابتدا ذخیره، سپس تست کنید.
- ایتا از توکن EitaaYar، روبیکا از شناسه کانال اختصاصی و Bot API v3، بله از توکن بازوی پدر و سروش از Bot API سازگار با قرارداد فعلی استفاده می‌کنند. قرارداد واقعی سروش/ایتا/روبیکا هنوز پذیرش میدانی ندارد. برای هر مقصد ابتدا متن و رسانه مجاز روی کانال آزمایشی ارسال کنید.
- قالب‌بندی غنی، آلبوم یکجا، برنامه‌ریزی ساعت دقیق روزانه، پاک‌سازی خودکار رسانه و پنل مرکزی چند پروژه باقی‌مانده‌اند. این نسخه نه آزمون نهایی Windows و نه پذیرش عملی پنج سرویس را دارد.

## ۸. توسعه و منابع

`main.py` API و runtime، `relayforge/database.py` پایگاه داده و صف، `source.py` روش‌های تلگرام، `gateways.py` اتصال‌دهنده‌ها، `engine.py` worker مستقل، `web/` رابط. آزمون‌ها در `tests/` و smoke در `smoke_runtime.py`. `requirements*.txt` نسخه‌های مشخص‌شده برای کاهش drift هستند؛ وابستگی‌های غیرمستقیم و Windows build هنوز باید در CI تأیید شوند.
