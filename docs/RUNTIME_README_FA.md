# RelayForge Desktop 4.3.5 — بازیابی خطای 503 Gemini و تنظیمات مستقل AI

مبنا: ZIP کامل نسخه 4.3.3. موتور انتشار و تبدیل قالب‌بندی تغییر نکرده است (فقط برچسب نسخه در engine.py تغییر کرده). این نسخه هنوز کاندید آزمون عملی ویندوز و API است.

## شروع سریع
1. نسخه قبلی را کاملاً متوقف و بسته کنید. کل data را پشتیبان بگیرید و فقط کپی آن را به پوشه تازه منتقل کنید. بازنشانی لازم نیست.
2. RUN_FROM_SOURCE_WINDOWS.bat را اجرا کنید. پس از تأیید واقعی، BUILD_EXE_WINDOWS.bat را اجرا کنید.
3. استودیو هوش مصنوعی ← راه‌اندازی هوش مصنوعی: تیک اجازه استفاده از سرویس خارجی و دکمه ذخیره وضعیت فعال‌سازی. نصب تازه و بازیابی پشتیبان غیرفعال هستند؛ وضعیت موجود هنگام ارتقا حفظ می‌شود.
4. کلید جداگانه OpenAI یا Gemini را در کارت مربوط وارد کنید و ذخیره کلید را بزنید. کلید OpenAI از https://platform.openai.com/api-keys و Gemini از https://aistudio.google.com/apikey گرفته می‌شود. اشتراک عادی چت، سهمیه API نیست.
5. دکمه «تست اتصال و دریافت آنلاین مدل‌ها» را بزنید. فهرست از API همان کلید گرفته می‌شود. مدل متن و صوت جدا هستند. دریافت فهرست برای هر سرویس به صورت دستی است؛ آخرین فهرست معتبر در نصب محلی نگهداری می‌شود. با تغییر کلید فهرست پاک می‌شود. در صورت نبود فهرست، انتخاب‌های اولیه نسخه قبلی با برچسب آفلاین و بدون تأیید دسترسی نمایش داده می‌شوند.
6. موتور و مدل پیش‌فرض و سقف روزانه (۱ تا ۱۰۰۰ درخواست تولید، پیش‌فرض ۱۰) را انتخاب و «ذخیره تنظیمات و مدل‌های پیش‌فرض» را بزنید. سقف تعداد درخواست است، نه سقف پول؛ درخواست ناموفق پس از رزرو نیز شمرده می‌شود. فهرست مدل‌ها از این سقف کم نمی‌کند. روز بر اساس UTC است.
7. در آزمایش تحلیل، متن را وارد کنید یا آخرین پست مجاز تلگرام را بخوانید. پروفایل برند و قالب را تنظیم کنید. برای سرویس خارجی رضایت همان درخواست را تیک بزنید، سپس تحلیل و پیش‌نمایش. خروجی را بازبینی کنید. گزینه کپی برای نتیجه بدون هشدار فعال می‌شود.
8. پادکست: مدل متن Gemini و مدل TTS را جدا انتخاب کنید؛ متن پادکست را بسازید، بازبینی کنید، رضایت مجدد بدهید و صوت WAV بگیرید. صوت تک‌گوینده یا دوگوینده قابل انتخاب است. هیچ خروجی AI خودکار منتشر نمی‌شود.

## امنیت و محدودیت
- کلید در سمت سرور با Fernet و کلید نصب ذخیره می‌شود و مقدار آن از API تنظیمات به مرورگر برنمی‌گردد. رمزگذاری در حالت سکون است؛ کسی که به فایل data و secrets.key دسترسی دارد می‌تواند کلیدها را بخواند. کل پوشه و پشتیبان را محرمانه نگه دارید. پشتیبان قابل حمل رمزگذاری‌شده کلیدهای ذخیره‌شده را هم منتقل و با کلید نصب مقصد دوباره رمزگذاری می‌کند. پس از بازیابی، AI غیرفعال و فهرست آنلاین پاک است. کلیدهای محیطی به پشتیبان منتقل نمی‌شوند.
- حذف کلید محلی ممکن است کلید متغیر محیطی قبلی را دوباره فعال کند؛ این وضعیت در پنل اعلام می‌شود. برای توقف کامل AI مجوز را خاموش کنید. درخواست در حال اجرا الزاماً لغو نمی‌شود.
- دریافت فهرست آنلاین از GET /v1/models و GET /v1beta/models انجام می‌شود. OpenAI نوع خروجی قابل پشتیبانی را در این فهرست به طور کامل اعلام نمی‌کند. فیلتر نام و متد برای انتخاب کاندیدهای متن/TTS است، نه تضمین قابلیت JSON یا سازگاری Gemini Interactions. اگر یک مدل خطای ۴۰۰/۴۰۴ می‌دهد، مدل دیگری انتخاب کنید؛ درخواست بدون retry خودکار است. مدل‌های 3.8 TTS طبق راهنمای فعلی Gemini مسیر اصلی صوت هستند. هیچ دسترسی زنده با کلید واقعی تأیید نشده.
- حالت محلی فقط قالب‌ساز و تحلیل واژه‌محور است. مدل خارجی بازنویسی، دسته‌بندی و پیشنهاد تیتر/هشتگ می‌دهد. کنترل واژگانی اعداد، تاریخ، لینک‌ها و عبارات محافظت‌شده تضمین صحت معنایی نیست. هر نتیجه نیازمند بررسی انسان است. AI خودکار روی موتور، زمان‌بندی یا صف هیچ تأثیری ندارد.

# RelayForge 4.3.1 — اصلاح قالب‌بندی + Gemini و صوت

## راه‌اندازی و ارتقا
- نسخه قبلی را با توقف امن متوقف و کاملاً ببندید. از تمام پوشه data کپی آفلاین امن بگیرید؛ فقط کپی را به نصب تازه انتقال دهید. دیتابیس و تاریخچه حذف یا بازنشانی نشوند. فایل START_HERE_FA.md و README_FA.md را مطالعه کنید.
- ابتدا RUN_FROM_SOURCE_WINDOWS.bat را اجرا کنید؛ پس از آزمون موفق واقعی BUILD_EXE_WINDOWS.bat را اجرا کنید. Python 3.12 و Nuitka 4.3.1 حفظ شده‌اند.

## اصلاح بولد (اولویت اصلی)
- بله: حذف fallback سراسری در وجود هشتگ و آندرلاین، تفکیک سطرهای بولد، اولویت بولد در همپوشانی، حفظ فاصله‌های بیرونی؛ در مرزهای غیر فاصله ممکن است یک فاصله برای رندر بله افزوده شود. حالت تک‌ستاره پیش‌فرض و حالت دو ستاره آزمایشی. علائم Markdown موجود در متن اصلی ممکن است توسط مقصد تعبیر شوند؛ در لاگ هشدار داده می‌شود. قالب‌های پیچیده پشتیبانی‌نشده ساده می‌شوند.
- ایتا: در مستند رسمی ایتایار parse_mode برای sendMessage و sendFile ذکر نشده؛ Markdown مستقیم تک/دو ستاره بدون پارامتر اضافی اضافه شد. HTML و Markdown با parse_mode آزمایشی قبلی حفظ شدند. هیچ فرمت ایتا را بدون دیدن نتیجه در کانال تضمین نمی‌کنیم.
- روبیکا: متادیتای Bold با UTF-16 به جای حذف کل قالب هنگام وجود ایموجی؛ حالت جایگزین codepoint برای آزمون. تلگرام native بدون تغییر، سروش plain (محدودیت پشتیبانی تأییدنشده).
- تنظیم قبلی ایتا/روبیکا عمداً بازنویسی نشده تا ارسال علامت‌های خام به کانال فعال ناخواسته رخ ندهد. موتور را متوقف کنید، منوی «قالب‌بندی پیام‌ها»، «روش‌های پیشنهادی»، انتخاب مقصد آزمایشی، «پیش‌نمایش آخرین پست واقعی ذخیره‌شده» یا «ارسال پیام آزمایشی واقعی». ظاهر بولد را در مقصد بررسی کنید. حالت مناسب را ذخیره و موتور را شروع کنید. در صورت شکست تک‌ستاره، حالت دو ستاره یا گزینه آزمایشی دیگر را جداگانه امتحان کنید. اگر هیچ حالت ایتا جواب نداد، plain را برگردانید؛ ممکن است API ایتایار اصلاً از قالب‌بندی پشتیبانی نکند. هیچ ارسال مجدد خودکار پس از پاسخ مبهم انجام نمی‌شود.
- پست‌های ذخیره‌شده قبل از 4.3 که entities ندارند قابل بازیابی از روی متن ساده نیستند؛ فقط پست تازه یا بازخوانی مجاز از مبدأ می‌تواند اطلاعات قالب را تأمین کند. هیچ ارسال موفق قبلی مجدداً صف نمی‌شود. پیش‌نمایش پست ذخیره‌شده، entities ورودی و payload خروجی را نشان می‌دهد. برای تست کپشن واقعی یک عکس با کپشن بولد جدید در کانال آزمایشی منتشر کنید.

## Gemini و TTS
کلید را از https://aistudio.google.com/apikey دریافت کنید. اشتراک مصرف‌کننده Gemini جایگزین اعتبار API نیست؛ دسترسی مدل/منطقه و هزینه در AI Studio بررسی شود. کلید فقط در متغیر محیطی برنامه است و در پشتیبان یا گزارش ثبت نمی‌شود.
در PowerShell از پوشه نرم‌افزار، پس از توقف کامل نسخه قبلی:

```powershell
$secure = Read-Host 'Gemini API key' -AsSecureString
$env:RELAYFORGE_GEMINI_API_KEY = [System.Net.NetworkCredential]::new('', $secure).Password
.\RUN_FROM_SOURCE_WINDOWS.bat
Remove-Item Env:RELAYFORGE_GEMINI_API_KEY -ErrorAction SilentlyContinue
```
برای نسخه کامپایل‌شده به جای BAT از ` .\RelayForge.exe ` استفاده کنید. متغیر فقط در این نشست و فرزندان آن موجود است؛ سرویس و Task Scheduler جداگانه به تنظیم محرمانه محیط نیاز دارند. از ذخیره کلید در فایل BAT و ارسال آن به دیگران خودداری کنید.

- استودیو هوش مصنوعی: مجوز AI خارجی را فعال و ذخیره کنید. Gemini و مدل انتخابی، متن دستی/آخرین نمونه ذخیره‌شده تلگرام، برند و دستور و تأیید ارسال هر درخواست. پیش‌نمایش و تحلیل بدون انتشار خودکار.
- صوت: «کپی متن اصلی بالا»، روخوانی تک‌گوینده یا «ساخت متن پادکست» برای تولید گفت‌وگوی دوگوینده. متن پیشنهادی با خطوط Host: / Guest: قابل ویرایش است. آن را بازبینی کنید، دو صدای متفاوت و سبک را انتخاب کنید، تأیید ارسال مجدد را بزنید و «تولید صوت WAV». پخش و دانلود در مرورگر؛ فایل به صورت خودکار منتشر یا روی سرور ذخیره نمی‌شود. برای تبدیل پست به پادکست دو درخواست جداگانه (متن و صوت) لازم است.
- سقف مشترک ۱۰ درخواست خارجی در روز UTC (OpenAI، Gemini و صوت)، بدون retry خودکار. سقف طول متن صوت ۶۰۰۰ نویسه، متن اولیه پادکست ۴۰۰۰ نویسه و حجم صوت ۱۶ MiB. API کلید و خروجی واقعی در این محیط در دسترس نبود. پشتیبانی مدل Gemini از فارسی مطابق راهنمای رسمی است؛ کیفیت تلفظ هنوز بررسی نشده. پیش‌نمایش AI و TTS هیچ اتصال خودکار به صف انتشار ندارند.
- کنترل واژگانی قیمت، تاریخ، لینک و اعداد برای خروجی متن؛ هشدار پادکست نیازمند بازبینی دستی است. صوت خودش بررسی معنایی یا شنیداری خودکار نشده است.

# RelayForge Studio 4.3.0 — Rich Text + AI Lab

**وضعیت: کاندید انتشار Desktop، نه نسخه تجاری Cloud.** نسخه پایه 4.2.0 دست‌نخورده نگه داشته شده است. ۱۳۴ آزمون محلی روی Python 3.13.5 در لینوکس پاس شده‌اند. کامپایل و آزمون Windows/Python 3.12 و سرویس‌های واقعی هنوز انجام نشده‌اند. 1. در 4.2 «توقف امن» بزنید و برنامه/سرویس/Task Scheduler را کاملاً ببندید. از **کل data** نسخه پایدار کپی آفلاین بگیرید. کلید `secrets.key`، نشست‌ها و رسانه‌ها را حفظ کنید؛ محرمانه هستند.
2. ZIP کامل 4.3 را در پوشه تازه مانند `C:\RelayForge43` استخراج کنید؛ فقط یک **کپی** از data قبلی را کنار `main.py` (یا بعد از ساخت کنار EXE) قرار دهید. هرگز دو نصب را همزمان روی همان کانال‌ها اجرا نکنید. پیش از ارتقا برنامه از دیتابیس قبلی پشتیبان محلی رمزگذاری‌شده می‌سازد. اگر حجم مانع پشتیبان‌گیری شد، از نسخه آفلاین و بررسی فنی استفاده کنید؛ از حذف فایل‌های داده خودداری کنید.

5. منوی «استودیو هوش مصنوعی» برای آزمایش آفلاین و اختیاری؛ نیازی به تغییر تنظیمات موتور یا بازنشانی نیست.

- ذخیره canonical entity با بازه نیمه‌باز codepoint در ستون جدید `source_messages.entities`؛ استخراج Bot API (`entities` و `caption_entities`) و Telethon (`MessageEntity…`). تبدیل UTF-16 دوطرفه برای تلگرام، ایموجی و نیم‌فاصله. پیشوند/پسوند قدیمی با جابه‌جایی offset سازگارند. در حالت BotFather آرشیو copyMessage متن قدیمی خوانده نمی‌شود و کپی مستقیم تلگرام تابع خود سرویس است.
- تلگرام: entities/caption_entities؛ bold، italic، underline، strikethrough، code، pre، text_link، blockquote و spoiler در حد entity معتبر. لینک HTTP/HTTPS معتبر. تست API واقعی باقی است.
- بله: Markdown با `*متن*` و `_متن_` برای بولد/ایتالیک ساده، پیش‌فرض فعال. در متن دارای نشانه‌های Markdown یا تودرتویی ناسازگار، افت قالب یا fallback متن ساده با هشدار. شکل ارسال فایل/کپشن باید در کانال واقعی تست شود.
- ایتا: HTML و Markdown آزمایشی با parse_mode؛ پیش‌فرض plain. از ایتایار تأیید رسمی کافی برای قالب‌بندی کانال پیدا نشد. ممکن است علامت یا تگ خام نمایش داده شود؛ پیش از ذخیره حالت، ارسال آزمایشی به کانال تست و بررسی دیداری. بدون آزمون مثبت، plain را حفظ کنید.
- روبیکا: گزینه metadata آزمایشی (Bold/Italic/Underline/Strike)، پیش‌فرض plain؛ پیام حاوی ایموجی astral به دلیل عدم تأیید قرارداد اندیس، به متن ساده برمی‌گردد. متادیتای متن و رسانه نیازمند تست واقعی است.
- سروش‌پلاس: plain؛ هیچ ادعای قالب‌بندی API یا حساب آزمایشی نداریم. لینک پنهان و سبک‌های پشتیبانی‌نشده در مقصد غیرتلگرام ممکن است حذف شوند؛ متن قابل خواندن باقی می‌ماند و هشدار ثبت می‌شود. هیچ تلاش مجدد خودکار با قالب دیگر پس از خطای ارسال انجام نمی‌شود.
- پیام‌های قدیمی بدون entity با مهاجرت ستون خالی دریافت می‌کنند. برای همان مبدأ و متن دقیقاً یکسان، پیمایش مجاز Telethon می‌تواند entity قدیمی را غنی کند؛ ارسال موفق قبلی مجدداً در صف قرار نمی‌گیرد. ارتقای reference-only BotFather به آرشیو محتوایی مطابق 4.1 همچنان می‌تواند مسیرهای جدید مجاز را صف کند؛ برای آزمایش روی کپی داده و موتور متوقف عمل کنید.

## AI Studio — آزمایشگاه بدون انتشار
- از 4.3.5، فقط پاسخ صریح HTTP 503 در Gemini حداکثر دو بار با فاصله ۲ و ۴ ثانیه به‌علاوه jitter تکرار می‌شود. هر تلاش از سقف محلی کم می‌شود؛ تغییر خودکار مدل و تکرار timeout یا 429 نداریم. توضیحات کامل در RELEASE_435_FA.md.
- حالت Local Preview: قالب‌ساز قطعی و دسته‌بندی واژه‌ای محدود، **مدل هوش مصنوعی زبانی نیست** و بازنویسی واقعی انجام نمی‌دهد. حتی بدون اینترنت و API کار می‌کند.
- پروفایل مستقل هر مسیر شامل برند، لحن، نام مخاطب/مقصد، دستور اختصاصی، قالب و عبارت‌های محافظت‌شده. قالب مجاز: `{body}` (دقیقاً یک بار)، `{brand}`, `{title}`, `{destination}`, `{hashtags}`. هیچ expression یا دسترسی attribute در قالب مجاز نیست.
- متن نمونه را دستی وارد کنید یا «آخرین پست مجاز تلگرام» را بزنید؛ فقط پیام جاری eligible، غیرمحافظت‌شده و دارای متن. نمونه‌ها به‌صورت خودکار به سرویس خارجی ارسال نمی‌شوند.
- مدل خارجی OpenAI (اختیاری): رابط مستقل Provider، میزبان ثابت HTTPS، بدون ابزار، بدون redirect، timeout کلی ۳۰ ثانیه، ۶۰۰۰ نویسه ورودی، سقف ۱۶۰۰ توکن خروجی، سقف قابل تنظیم تلاش‌های تولید خارجی در روز UTC (پیش‌فرض ۱۰)؛ رزرو پیش از تماس، بدون retry. این سقف تعداد درخواست است، نه تضمین هزینه ریالی؛ هزینه به مدل و تعرفه بستگی دارد و پشتیبان قدیمی می‌تواند شمارنده را برگرداند. برای مصرف واقعی تنظیمات محدودیت حساب ارائه‌دهنده را نیز کنترل کنید. دسترسی تنها در کشور/حساب مجاز؛ مدل و دسترسی ممکن است متفاوت باشند.
- کلیدهای AI در نسخه فعلی از داشبورد به‌صورت رمزگذاری‌شده ذخیره می‌شوند؛ متغیر محیطی مسیر جایگزین است. برای اجرای اختیاری با PowerShell در پوشه برنامه:

```powershell
$secure = Read-Host 'OpenAI API key' -AsSecureString
$env:RELAYFORGE_AI_API_KEY = [System.Net.NetworkCredential]::new('', $secure).Password
.\RUN_FROM_SOURCE_WINDOWS.bat
Remove-Item Env:RELAYFORGE_AI_API_KEY -ErrorAction SilentlyContinue
```

برای EXE نیز آن را از همان PowerShell اجرا کنید. کلید در محیط همان فرایند است، نه در فایل ZIP. برنامه را در حساب امن اجرا کنید. اشتراک ChatGPT به‌تنهایی اعتبار API محسوب نمی‌شود.
- در داشبورد مجوز AI خارجی را روشن و ذخیره کنید، موتور OpenAI و مدل را انتخاب و برای هر پیش‌نمایش ارسال متن و پروفایل را صریحاً تأیید کنید. پیش‌فرض خاموش است؛ بازیابی پشتیبان آن را خاموش می‌کند. متن خصوصی بدون مجوز وارد نکنید.
- کنترل واژگانی اعداد، تاریخ، قیمت، لینک، منشن، نقل‌قول و عبارت‌های دستی؛ حذف یا اضافه شدن حقایق قابل تشخیص، خروجی را مسدود و متن اصلی را بازمی‌گرداند. این **راستی‌آزمایی معنایی کامل نیست**؛ نام‌ها را در عبارت‌های محافظت‌شده وارد کنید و هر خروجی را دستی بازبینی کنید. خروجی تحلیل هرگز به صف انتشار وارد نمی‌شود؛ فقط پیش‌نمایش/کپی. مدل خارجی با mock بررسی شده است؛ دسترسی زنده و کیفیت واقعی مدل تأیید نشده‌اند.
- پروفایل و حالت قالب در پشتیبان تنظیمات ذخیره می‌شوند؛ API key محیطی ذخیره نمی‌شود. بدون AI موتور قدیمی مستقل کار می‌کند. اتصال خودکار AI به صف، تأیید سردبیر، RAG، اشتراک و multi-tenant مربوط به مراحل بعدی هستند.

## مهاجرت بدون وارد کردن دوباره APIها از 4.1
1. در نسخه 4.1 موتور را متوقف و برنامه را کاملاً ببندید (Task Scheduler/Service نیز متوقف باشد).
2. کل پوشه `data` را در محلی امن کپی کنید؛ خصوصاً `relayforge.sqlite3`، `secrets.key`، `dashboard-key.txt`، نشست‌ها و `media`.
3. ZIP نسخه 4.2 را در پوشه تازه مانند `C:\RelayForge42` استخراج کنید. فقط یک کپی از data قبلی را کنار main.py قرار دهید؛ اگر EXE ساختید، data کنار EXE باشد. همزمان دو نسخه اجرا نشوند. هنگام نخستین اجرا روی دیتابیس قبلی، پیش از مهاجرت، پشتیبان خودکار دیتابیس و کلید ساخته می‌شود. پشتیبان اصلی آفلاین را همچنان حفظ کنید.

## پشتیبان رمزگذاری‌شده و بازیابی
- از منوی «عملیات و پشتیبان» نوع پشتیبان را انتخاب کنید: فقط تنظیمات (مبدأ، APIها و مقصدها بدون تاریخچه، صف و نشست)، دیتابیس کامل (تنظیمات، تاریخچه و صف)، یا کامل (دیتابیس، فایل‌های رسانه، نشست‌های شناخته‌شده و لاگ‌ها). رمز مستقل ۱۲ تا ۲۵۶ نویسه و تکرار رمز را وارد کنید و «ایجاد و دانلود پشتیبان» را بزنید.
- فایل `.rfbackup` دارای ZIP فشرده داخلی و رمزگذاری احرازشده AES-256-GCM با salt/nonce تصادفی و scrypt است؛ ZIP عادی نیست. رمز جدا از فایل نگهداری شود. سقف مجموع فایل‌های خام و ZIP داخلی ۱۲۸ MiB است؛ برای آرشیو بزرگ از کپی آفلاین کل data استفاده کنید. پشتیبان کامل فقط با موتور متوقف ممکن است. رمزهای زمان‌بندی داخل پشتیبان صادر نمی‌شوند. رمز داشبورد نصب مقصد حفظ می‌شود؛ برای مهاجرت کامل خود رمز پنل، کپی آفلاین data لازم است.
- بازیابی: فایل و رمز را در همان بخش انتخاب کنید. «فقط تنظیمات» دیتابیس جاری را با تنظیمات جایگزین و تاریخچه و صف را از دیتابیس فعال حذف می‌کند؛ «دیتابیس و سوابق» تاریخچه و صف پشتیبان را برمی‌گرداند. در صورت وجود پشتیبان کامل، انتخاب نشست و رسانه نیز ممکن است؛ لاگ‌های قبلی در `data/restored_logs` آرشیو می‌شوند. فایل‌های فعلی نشست/رسانه اگر انتخاب نشده باشند دست‌نخورده می‌مانند. دو تأیید را انجام دهید؛ پس از اعتبارسنجی، برنامه را کاملاً ببندید و دوباره اجرا کنید. تا آن زمان عملیات تغییردهنده مسدود می‌شود.
- هنگام راه‌اندازی، نسخه بازگشت از دیتابیس فعلی و فایل‌های انتخاب‌شده در `data/backups/restore-before-*` ذخیره می‌شود. اعمال بازیابی تحت قفل اجرا انجام و توکن‌ها با کلید نصب مقصد دوباره رمزگذاری می‌شوند. تمام مقصدها خاموش می‌شوند و موتور خودکار شروع نمی‌کند. بازیابی پشتیبان قدیمی ممکن است صف قدیمی داشته باشد: پیش از فعال‌سازی، سابقه واقعی کانال‌ها را بررسی کنید. اگر اعمال بازیابی به دلیل دسترسی یا فضای دیسک شکست خورد، برنامه را دوباره اجرا نکنید مگر بعد از رفع علت؛ `restore_pending` را حفظ کنید. در صورت نیاز با نسخه آفلاین data یا نسخه بازگشت، در حالت توقف کامل بازیابی دستی انجام دهید.
- پشتیبان‌های خودکار روزانه: در پنل روشن کنید و رمز اختصاصی تعیین کنید. هر ۲۴ ساعت در زمان اجرای برنامه بررسی و ایجاد می‌شود؛ اگر نوع کامل انتخاب شود تا توقف موتور به تعویق می‌افتد. زمان آخرین موفقیت نمایش داده می‌شود. در حالت خاموش بودن ویندوز پشتیبان ایجاد نمی‌شود. رمز زمان‌بندی در دیتابیس با کلید محلی محافظت می‌شود. پشتیبان‌ها خودکار حذف نمی‌شوند؛ فضای دیسک را پایش کنید.
- پیش از بازنشانی و مهاجرت نسخه، پشتیبان دیتابیس رمزگذاری‌شده با رمز محلی (محتوای `data/secrets.key`، بدون خط پایان) ساخته می‌شود. فایل کلید و پوشه data را محرمانه نگه دارید. اگر حجم دیتابیس بیش از ۱۲۸ MiB باشد یا فضای کافی نباشد، عملیات حفاظتی متوقف می‌شود و نیاز به پشتیبان آفلاین/بررسی فنی دارد. این پشتیبان محلی جایگزین نسخه قابل انتقال با رمز مستقل نیست.
- روی ویندوز دسترسی NTFS پوشه data و محل پشتیبان را به حساب سرویس/کاربر مالک محدود کنید؛ رمزگذاری پشتیبان، نشست‌ها و کلیدهای محلی موجود روی دیسک را به‌خودی‌خود رمزگذاری نمی‌کند. فایل بازگشت آفلاین شامل داده و کلید است؛ آن را به دیگران ندهید.

## ارسال‌های نامطمئن و بازنشانی
- عملیات و پشتیبان → «نمایش ارسال‌های نامطمئن». تعداد کل و حداکثر ۵۰۰ رکورد اول نمایش داده می‌شود. انتخاب تکی/جمعی، تلاش مجدد، تأیید ارسال یا رد کردن وجود دارد؛ رد کردن همه شامل همه رکوردهاست و دو تأیید می‌خواهد. فقط وقتی مطمئن هستید پیام رسیده آن را تأیید کنید. تلاش مجدد می‌تواند پیام تکراری بسازد.
- بازنشانی: موتور را متوقف کنید. دکمه بازنشانی تعداد نامطمئن‌ها را اعلام می‌کند و می‌توانید پس از تأیید صریح، همه را رد کرده و عملیات جدید را شروع کنید. قبل از این اقدام پشتیبان خودکار ایجاد می‌شود؛ تاریخچه بایگانی و مقصدها غیرفعال می‌شوند. پیام‌های منتشرشده از کانال حذف نمی‌شوند.

## روبیکا
- طبق https://rubika.ir/botapi و https://rubika.ir/botapi/group-channel ، بات را مدیر کانال و دارای مجوز انتشار کنید. با همان بات اختصاصی در کانال منشن یا پیام مربوط به بات ایجاد کنید. در مقصد روبیکا، توکن را در حالت خاموش ذخیره کنید؛ سپس «تشخیص شناسه کانال» را بزنید. برنامه ۵۰ رویداد اخیر قابل دسترس را با getUpdates بررسی و شناسه‌های کانال را با getChat تأیید می‌کند. این فهرست همه کانال‌های حساب نیست؛ اگر رویداد در دسترس نیست شناسه داخلی را دستی وارد کنید. از بات مشترک با مصرف‌کننده دیگر getUpdates استفاده نکنید. کانال را انتخاب و مقصد را ذخیره کنید. تست API شناسه و نوع کانال را بررسی می‌کند؛ مجوز واقعی انتشار فقط با پیام آزمایشی اثبات می‌شود. وضعیت خطای API روبیکا در گزارش ثبت می‌شود.

## سروش‌پلاس — حساب کاربری آزمایشی
- حالت Bot API قبلی حفظ شده است. اگر بات اجازه افزودن به کانال ندارد، فقط با حسابی که خودش مالک یا دارای مجوز انتشار کانال است از حالت حساب استفاده کنید. هیچ محدودیت یا مجوز سرویس دور زده نمی‌شود.
- حالت اختیاری **فقط اجرای سورس**: `RUN_EXPERIMENTAL_SPLUS_WINDOWS.bat` نصب جداگانه کتابخانه شخص ثالث SPlusthon 1.1.4 (GPLv3) را با تأیید صریح انجام می‌دهد. مستندات: https://shayanheidari01.github.io/SPlusthon/ و https://pypi.org/project/SPlusthon/1.1.4/ . کتابخانه همراه بسته توزیع نشده و در EXE پیش‌فرض نصب نمی‌شود. پیش از نصب، مجوز و امنیت وابستگی را بررسی کنید؛ ممکن است API تغییر کند. ورود واقعی و ارسال با حساب در این محیط انجام نشده است.
- موتور را متوقف کنید. در کارت سروش‌پلاس، شماره با کد کشور، درخواست کد و تأیید ورود را انجام دهید؛ در صورت درخواست رمز دومرحله‌ای، فیلد کد را خالی بگذارید و رمز را وارد کنید. سپس «کانال‌های مجاز» را بزنید و انتخاب کنید. مقصد خاموش ذخیره می‌شود؛ تست API و پیام آزمایشی را انجام دهید و فقط پس از تأیید فعال کنید. نشست محلی مستقل هر مسیر در data نگهداری می‌شود. رمز/کد تأیید در دیتابیس ذخیره نمی‌شود. برای تغییر کانالی که سابقه صف دارد، مقصد تازه بسازید. پیش از بسته‌بندی/توزیع تجاری افزونه، الزامات GPLv3 بررسی شود.

## راهنمای سریع ۴.۱ — رفع مشکل بله و آرشیو

### حذف مقصدها
از نمای کلی، موتور را متوقف کنید. در «مقصدها و APIها» تیک مقصدهای اضافی را بزنید و «حذف مقصدهای انتخاب‌شده» را انتخاب کنید؛ برای یک مقصد دکمه «حذف مقصد» روی همان کارت است. دو بار تأیید کنید. مقصد از فهرست فعال حذف (بایگانی) و توکن ذخیره‌شده آن خالی می‌شود؛ تاریخچه در گزارش‌ها باقی می‌ماند. صف منتظر ردشده ثبت می‌شود. اگر ارسال نامطمئن یا در جریان وجود دارد ابتدا آن را تعیین تکلیف کنید. حذف گروهی یک تراکنش است. پاک‌کردن صف فقط پیام‌های queued همان مقصد را رد می‌کند. توقف/ادامه مستقل بدون خاموش کردن سایر مقصدها ممکن است؛ ارسال در جریان ممکن است تکمیل شود. تکرار مقصد با همان شناسه متنی در یک سرویس محدود شده و هنگام افزودن backlog، ارسال موفق همان شناسه در همان عملیات دوباره صف نمی‌شود. شناسه‌های معادل با قالب‌های متفاوت و عملیات تازه هنوز خطر تکرار دارند.

### ارسال پست‌های قدیمی تلگرام به بله و دیگر مقصدها
1. موتور را متوقف کنید. در مبدأ، روش **API ID / Hash** را انتخاب کنید. از https://my.telegram.org/apps مشخصات برنامه را دریافت و شماره حساب تلگرام خود را با کد کشور وارد کنید.
2. اگر قبلاً با BotFather در همین عملیات پیام گرفته‌اید، همان شناسه کانال مادر را دقیقاً نگه دارید، گزینه «ارتقای همان کانال به API Hash یا اصلاح اطلاعات ورود حساب» را فعال کنید و ذخیره کنید. در صورت نبود شناسه عددی ذخیره‌شده، برنامه از بات قبلی یک بررسی خواندنی می‌گیرد؛ این بررسی فقط مالکیت/شناسه فعلی را نشان می‌دهد، نه اینکه نام کاربری در گذشته هیچ‌وقت تغییر نکرده باشد. اگر نام کانال تغییر کرده یا از هویت قبلی مطمئن نیستید، به جای این مهاجرت از پروژه جدید استفاده کنید. قبل از خواندن آرشیو، شناسه عددی کانال با شناسه ذخیره‌شده مقایسه می‌شود.
3. درخواست کد و سپس تأیید ورود را انجام دهید؛ اگر رمز دومرحله‌ای دارید همان‌جا وارد کنید. بعد تست مبدأ را بزنید.
4. آرشیو را فعال و بازه مثلاً ۳۰ تا ۲۰۰ را وارد کنید. Realtime اختیاری و مستقل است. برای بازخوانی از شماره شروع، پس از ذخیره «پیمایش مجدد بازه ذخیره‌شده» را بزنید. شناسه‌های قبلاً ثبت‌شده تکرار نمی‌شوند؛ رکوردهای کپی BotFather با محتوای واقعی تکمیل می‌شوند.
5. مقصد بله را فعال کنید، توکن بازوی **بله** (نه BotFather تلگرام) و شناسه کانال بله را وارد کنید. بازو باید در کانال مجوز انتشار داشته باشد. برای پیام‌هایی که قبلاً با محتوای واقعی ثبت شده‌اند، تیک «صف‌کردن پیام‌های قبلی همین عملیات» را هنگام ذخیره بزنید. این گزینه تمام پیام‌های واجد شرایط قبلی همین عملیات را شامل می‌شود، نه فقط بازه تازه؛ اگر نمی‌خواهید چنین شود، پروژه جداگانه بسازید. مقصدهای دیگر نیز مستقل تنظیم می‌شوند.
6. با موتور متوقف، «تست API» و سپس «ارسال پیام آزمایشی» را بزنید؛ دومی یک پیام واقعی منتشر می‌کند. اگر موفق شد، ابتدا بازه کوچک چند پست را امتحان و بعد موتور را شروع کنید.

BotFather به‌تنهایی متن و رسانه آرشیو قدیمی را نمی‌خواند؛ آن روش فقط کپی مستقیم آرشیو به تلگرام یا دریافت پیام‌های جدید را پوشش می‌دهد. هیچ محتوای محافظت‌شده‌ای دور زده نمی‌شود. فرمت‌های خاص، آلبوم کامل، محدودیت اندازه رسانه و قالب متن سرویس مقصد همچنان محدودیت دارند. آرشیو و ارسال واقعی در حساب‌های شما هنوز آزمایش نشده‌اند.

### لاگ و گزارش
روی کارت مقصد، شمارنده‌های صف، موفق، خطا، نامطمئن و ردشده دیده می‌شوند. آخرین خطا و زمان تلاش بعدی نشان داده می‌شود. صفحه «لاگ و وضعیت ارسال» فیلتر مقصد (حتی بایگانی‌شده)، جست‌وجو، صفحه‌بندی ۱۰۰ رکورد و دریافت JSON دارد. برای خروجی پایدار، موتور را متوقف کنید. جست‌وجوی ارسال‌ها شامل وضعیت، شناسه پیام، خطا و نام کانال است. علت رد شدن محتوا، عدم ورود آرشیو BotFather به صف بله، شروع ارسال، خطای API و شناسه پیام مقصد ثبت می‌شود. از این نسخه رویدادهای DB به‌صورت خودکار پس از ۳۰۰۰ رکورد حذف نمی‌شوند؛ حجم دیسک را دوره‌ای بررسی کنید. لاگ فایل `data/logs/relayforge.log` چرخشی است (حدود ۳ مگابایت و ۵ نسخه قبلی)؛ DB منبع اصلی گزارش است. اطلاعات پیش‌تر حذف‌شده بازیابی نمی‌شوند. توکن‌ها و URL خام در شرح خطا ثبت نمی‌شوند. خروجی گزارش ممکن است شناسه کانال‌ها و جزئیات عملیاتی داشته باشد؛ عمومی منتشر نکنید.

## ۱. اجرا

- ویندوز 10/11 و Server 2019 x64 هدف هستند؛ Python 3.12 x64 با Python Launcher نصب باشد. برای اجرای سورس `RUN_FROM_SOURCE_WINDOWS.bat` را اجرا کنید. برای ساخت EXE `BUILD_EXE_WINDOWS.bat` را اجرا کنید. اسکریپت تست‌ها را پاس نکرده به کامپایل نمی‌رود؛ پس از کامپایل نیز خود EXE را با پایگاه داده موقت و HTTP محلی آزمایش می‌کند. هیچ توکن واقعی برای تست لازم نیست.
- بعد از اجرای برنامه، آدرس `http://127.0.0.1:8765` را باز کنید. کلید ورود در `data\dashboard-key.txt` است. این کلید، توکن‌ها و فایل‌های session را به اشتراک نگذارید. موتور در نصب جدید خاموش است. پس از تنظیم مبدأ و مقصدها، دکمه شروع انتشار را بزنید.
- برای ساخت ویندوز، ZIP خروجی `RelayForge_v4.1.0_WINDOWS_EXE.zip` تنها پس از موفقیت تست و کامپایل و smoke test ایجاد می‌شود. سورس Python در ZIP اجرایی نهایی توزیع نمی‌شود؛ کامپایل Nuitka مانع مطلق مهندسی معکوس نیست و HTML/JS قابل مشاهده است.

## ۲. انتخاب روش دریافت

| روش | آرشیو | دریافت زنده | فیلتر محتوا |
|---|---|---|---|
| BotFather | فقط copyMessage به مقصد تلگرام با شناسه شروع و پایان | دریافت channel_post، ارسال به همه مقصدهای فعال | فقط وقتی آرشیو BotFather خاموش است |
| API ID/Hash (Telethon) | خواندن محتوای مجاز و ارسال به همه مقصدها | NewMessage و پیمایش جبرانی پس از اتصال مجدد | متن، کپشن، هشتگ و کلمات |

در حالت BotFather ربات را ادمین مبدأ کنید. برای کپی مستقیم آرشیو، بات مقصد نیز باید به مبدأ و مقصد دسترسی داشته باشد. شماره‌ها Message ID واقعی هستند، نه ترتیب پست. هر پست آرشیو با شناسه ثبت می‌شود؛ وجود همه پست‌ها یا موفقیت کپی تضمین نمی‌شود. خطاهای ارسال در صف همان مقصد قابل تعیین تکلیف‌اند. برای انتشار آرشیو ایتا، بله، روبیکا و سروش، API ID/Hash لازم است. Bot API به متن تاریخچه دلخواه دسترسی نمی‌دهد و آپدیت‌ها پس از حداکثر ۲۴ ساعت ممکن است از دست بروند. حفاظت محتوا دور زده نمی‌شود.

در حالت API Hash، از my.telegram.org کلیدهای برنامه را بگیرید، شماره حساب خود را وارد کنید، ذخیره کنید، درخواست کد و سپس تأیید ورود را انجام دهید. برنامه فقط برای حساب و محتوا با مجوز استفاده شود. نشست‌های نسخه ۴ با نام وابسته به مشخصات حساب ذخیره می‌شوند؛ پس از مهاجرت از ۳ ممکن است ورود مجدد نیاز باشد. نشست قبلی حذف نمی‌شود. کد ورود را به فرد دیگری ندهید.

آرشیو و Realtime مستقل هستند: بازه ۳۰ تا ۲۰۰ فقط آرشیو را محدود می‌کند؛ پست جدید ۲۰۱ نیز در صورت فعال بودن Realtime به صف می‌رود. حالت ارسال فوری هر مقصد فاصله صفر دارد؛ فاصله ۱۰۸۰۰ ثانیه برابر سه ساعت است. اولویت پیام‌های زنده برای مقصد فوری است. برای جلوگیری از رفتار ناخواسته، تغییر تنظیمات اصلی هنگام اجرای موتور مسدود است؛ ابتدا توقف امن بزنید.

## ۳. مقصدها و فیلتر

پنج نوع پیام‌رسان پیش‌فرض و حداکثر ۵۰ مسیر مقصد مستقل. با «افزودن مقصد» می‌توانید چند کانال تلگرام یا چند کانال از یک سرویس تعریف کنید. هر مسیر توکن، شناسه کانال و زمان‌بندی جدا دارد. فقط مقصدهای فعال صف جدید دریافت می‌کنند. گزینه «صف‌کردن پیام‌های قبلی همین عملیات» پیش‌فرض خاموش است. برای ارسال آرشیو ذخیره‌شده به مقصد جدید آن را صریحاً انتخاب کنید. برای تغییر توکن همان مقصد، ابتدا موتور را متوقف کنید و توکن را ذخیره کنید؛ سابقه حذف نمی‌شود. تغییر شناسه مقصد دارای سابقه در عملیات فعال مسدود است؛ مقصد جدید بسازید یا عملیات را بازنشانی کنید.

در صفحه مبدأ، فیلتر را روشن کنید و عبارت‌ها را با ویرگول فارسی یا انگلیسی جدا کنید. نوع تطبیق حداقل یکی یا همه؛ کلمات ممنوع همیشه پیام را رد می‌کنند. هشتگ دقیق بررسی می‌شود، کلمه کلیدی جستجوی زیررشته‌ای است. متن قبل/بعد اختیاری است. فیلتر فقط پیام‌هایی را که پس از تنظیم وارد می‌شوند بررسی می‌کند؛ صف قبلی بازنویسی نمی‌شود. آرشیو BotFather با فیلتر یا افزودن متن مجاز نیست.

## ۴. خطا و بازیابی

- قطعی پیش از ارسال و HTTP 429: تلاش مجدد امن بعد از حداقل ۳۰ ثانیه و رعایت Retry-After. در قطع پاسخ بعد از POST یا پاسخ نامعتبر، وضعیت uncertain ذخیره و فقط همان مسیر متوقف می‌شود؛ دستی مقصد را بررسی کنید. پاسخ HTTP 5xx نیز نامطمئن است. هیچ تضمین exactly-once بدون پشتیبانی مقصد وجود ندارد.
- سه خطای قطعی متوالی، همان مقصد را غیرفعال می‌کند. با اصلاح و فعال‌سازی دوباره مسیر ادامه دهید. خطاهای رسانه قبل از ارسال به تعویق می‌افتند. برنامه وب در قطعی اینترنت بسته نمی‌شود.
- توقف موتور، ارسال در جریان را محافظه‌کارانه نامطمئن علامت می‌زند. بعد از ری‌استارت، موتور فقط اگر قبلاً از پنل روشن بوده دوباره روشن می‌شود. تاریخچه و صف ذخیره می‌شوند.
- صفحه لاگ و وضعیت ارسال: تعیین تکلیف دستی failed/uncertain با retry، mark sent یا skip. قبل از retry وضعیت واقعی کانال را بررسی کنید.
- کش رسانه سقف عملیاتی اولیه ۱ گیگابایت و حداقل فضای آزاد دارد؛ دانلود Bot API ابری تا ۲۰ MB (محدودیت تلگرام). سقف فایل تنظیم‌شده نیز رعایت می‌شود. فایل‌های قدیمی خودکار حذف نمی‌شوند تا ارسال‌های معوق آسیب نبینند؛ پاک‌سازی خودکار کامل و حفظ آلبوم یکجا هنوز توسعه نیاز دارند.

## ۵. بازنشانی عملیات و مهاجرت از نسخه ۳

ابتدا نسخه ۳ را کاملاً متوقف کنید. از کل پوشه `data` (DB، secrets.key، session، media، logs و dashboard-key) پشتیبان رمزگذاری‌شده بگیرید. **هیچ فایل واقعی شما در بسته وجود ندارد.** نسخه ۴ را در پوشه تازه استخراج کنید و فقط کپی پوشه data را در کنار EXE یا main.py قرار دهید. مهاجرت DB افزودنی است و تاریخچه حفظ می‌شود. قبل از کپی داده حتماً از داشبورد نسخه قبلی دکمه توقف موتور را بزنید تا run_enabled=false ذخیره شود؛ اگر وضعیت روشن قبلی باقی مانده باشد، نسخه جدید هنگام اجرا موتور را آغاز می‌کند. پوشه قبلی را تا آزمون واقعی نگه دارید.

در تب عملیات، Backup یک نسخه سازگار SQLite و کلید رمزنگاری می‌سازد؛ رسانه و session در این Backup خودکار نیستند. برای پشتیبان کامل، در حالت توقف تمام پوشه data را کپی کنید. از فایل‌های کلید و پشتیبان محافظت کنید.

«بازنشانی با دو تأیید»: عملیات فعلی بایگانی، صف‌های در انتظار رد و مقصدها غیرفعال می‌شوند. تاریخچه موفق قبلی حفظ می‌شود و مبدأ و مقصد برای عملیات تازه قابل تنظیم هستند. ارسال‌های نامطمئن باید ابتدا تعیین تکلیف شوند. این کار پست‌های منتشرشده را حذف نمی‌کند و ارسال مجدد ممکن است تکراری باشد.

## ۶. چند پروژه، اجرای دائمی Windows

`START_PROJECT.bat` در بسته اجرایی، نام پروژه و پورت محلی منحصربه‌فرد می‌گیرد. هر پروژه دیتابیس و کلید جدا دارد. در سورس:

```
py -3.12 main.py --data-dir projects\news --port 8766
py -3.12 main.py --data-dir projects\education --port 8767
```

هر نمونه فقط یک کانال مادر دارد؛ چند پروژه را جداگانه اجرا کنید. از یک BotFather token برای getUpdates همزمان در چند پروژه استفاده نکنید. پنل مرکزی سوییچ پروژه‌ها هنوز پیاده نشده است.

برای VPS، Task Scheduler پیشنهاد می‌شود: `INSTALL_AUTO_START.ps1` را در PowerShell با دسترسی مدیر و حساب اختصاصی کم‌اختیار اجرا کنید. تسک At startup ثبت می‌شود؛ پس از تست، Disconnect RDP مشکلی ندارد. برنامه را از مسیر ثابت و با ACL محدود اجرا کنید. از حساب عادی سرویس استفاده کنید، نه Administrator. برای نصب اختیاری Windows Service، اسکریپت `INSTALL_SERVICE_WINDOWS.ps1` در Program Files محافظت‌شده و data در ProgramData با ACL محدود؛ حساب اختصاصی غیرادمین دارای Log on as a service لازم است. این مسیر هنوز روی ویندوز آزمایش نشده است. هر دو روش را همزمان نصب نکنید. نصب/حذف Task و Service از داخل داشبورد فعلاً انجام نمی‌شود. برای توقف/حذف از ابزار رسمی Windows استفاده کنید. تنظیمات موتور در DB باقی می‌ماند.

## ۷. امنیت و حدود تأیید

- localhost فقط؛ پورت را روی اینترنت عمومی باز نکنید. از Remote Desktop یا تونل امن استفاده کنید.
- توکن‌ها در SQLite با Fernet رمزگذاری می‌شوند، ولی کلید روی همان دیسک است. ACL و امنیت حساب سیستم ضروری است. توکن‌ها و OTP به صورت عمومی نمایش داده نمی‌شوند.
- تست Telegram و Bale تلاش می‌کند getMe/getChat/getChatMember را بدون ارسال بررسی کند. ایتا، روبیکا و سروش فعلاً تست اعتبار API دارند؛ مجوز واقعی انتشار باید با کانال آزمایشی تأیید شود. خطای 404 ممکن است مسیر API/توکن نامعتبر باشد؛ ابتدا ذخیره، سپس تست کنید.
- ایتا از توکن EitaaYar، روبیکا از شناسه کانال اختصاصی و Bot API v3، بله از توکن بازوی پدر و سروش از Bot API سازگار با قرارداد فعلی استفاده می‌کنند. قرارداد واقعی سروش/ایتا/روبیکا هنوز پذیرش میدانی ندارد. برای هر مقصد ابتدا متن و رسانه مجاز روی کانال آزمایشی ارسال کنید.
- قالب‌بندی غنی، آلبوم یکجا، برنامه‌ریزی ساعت دقیق روزانه، پاک‌سازی خودکار رسانه و پنل مرکزی چند پروژه باقی‌مانده‌اند. این نسخه نه آزمون نهایی Windows و نه پذیرش عملی پنج سرویس را دارد.

## ۸. توسعه و منابع
